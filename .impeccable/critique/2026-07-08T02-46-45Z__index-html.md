# Anti-Patterns Verdict

Does this look AI-generated? Partially. It is cleaner than a default AI portfolio, but it still carries several recognizable tells: dark minimal page, tiny uppercase section labels, numbered project markers, Inter as the main face, and a very safe card grid. The screenshots help because they are real project evidence; without them, the page would feel much more template-like.

LLM assessment: the strongest issue is not visual ugliness; it is under-commitment. The page says premium minimalist, but the system behind it is still the old "Boring" microVM design language. The portfolio needs a stronger personal point of view, not more decoration.

Deterministic scan: detector found 4 issues in `index.html`: overused font at line 12, design-system radius drift at line 228, single-font warning at line 12, and numbered section markers across project cards. The single-font warning is partly a false positive because JetBrains Mono is used for labels and UI details, but the page still depends heavily on Inter for its voice.

Visual overlays: no reliable user-visible overlay is available. Browser injection was not run because the browser automation surface was unavailable and Playwright's Chromium binary is not installed locally.

# Overall Impression

The portfolio has a credible base: dark, quiet, direct, and project-led. The biggest opportunity is to make it feel intentionally "Dika Laksana" rather than a clean dark portfolio that could belong to any backend engineer.

# Priority Issues

## [P1] The design system and product intent are out of sync

Why it matters: `DESIGN.md` still describes a "Boring" microVM product, while `PRODUCT.md` now defines a premium minimalist personal portfolio. That mismatch will keep future design changes biased toward terminal/developer-product tropes instead of personal brand clarity.

Fix: Update `DESIGN.md` around the portfolio identity: premium minimalist, proof-led, restrained, personal, with project screenshots as the primary visual material. Keep the black palette if desired, but stop treating terminal green and microVM language as the source of truth.

Suggested command: `$impeccable document index.html`

## [P1] The hero is too empty for a premium portfolio

Why it matters: The first viewport has a lot of unused space and only a name, label, generic positioning sentence, and contact button. Premium minimalism still needs a focal decision. Right now it reads sparse more than deliberate.

Fix: Add one strong proof element or identity element near the hero: a compact selected-project strip, a role/outcome statement, or a small portrait/artifact treatment. Keep it quiet, but give the opening fold a reason to be memorable.

Suggested command: `$impeccable layout index.html`

## [P2] Project cards carry real evidence but generic structure

Why it matters: The screenshots are strong, but the repeated `01 / Dashboard`, `02 / Fleet`, `03 / Field Ops`, `04 / Commerce` scaffolding is a common AI/editorial pattern. The card copy explains categories more than impact.

Fix: Replace numbered markers with more useful evidence labels: role, domain, year, or contribution type. Add one concise outcome line per project where possible, such as "risk lifecycle tracking for DITJEN P2P" or "fleet visibility and trip history workflows."

Suggested command: `$impeccable clarify index.html`

## [P2] Typography is competent but not distinctive

Why it matters: Inter is readable, but for a premium portfolio it is also generic. The detector flagged it correctly. The current typography does not create enough personal signature.

Fix: Keep Inter for body if you want, but introduce a more distinctive display face or tune the type system harder: tighter hierarchy, larger but controlled section headings, less repeated uppercase tracking, and clearer contrast between portfolio voice and metadata.

Suggested command: `$impeccable typeset index.html`

## [P3] Deployment details will break outside local file preview

Why it matters: The favicon uses `/Users/dikalaksana/Downloads/IMG_4463.JPG`, which only works on this Mac with a `file://` preview. Once deployed, the favicon will fail.

Fix: Move the image into the project, ideally `assets/favicon.jpg` or `assets/profile/favicon.jpg`, then reference it with a relative path.

Suggested command: `$impeccable harden index.html`

# Persona Red Flags

Recruiter scanning in 45 seconds: The project screenshots help, but the hero does not immediately state seniority, strongest domain, or what kind of role/opportunity fits. They may scroll, but the first fold does not do enough filtering.

Engineering manager evaluating credibility: The project evidence is visual, but the project copy lacks contribution scope. "What exactly did he build?" is not consistently answered from the cards alone.

Founder or collaborator looking to contact: The `Discuss a Project` button is visible, but WhatsApp has no specific recipient number. That path can feel broken or indirect.

# Minor Observations

- The custom scrollbar radius at line 228 is outside `DESIGN.md` token scale. This is minor, but it shows token drift.
- The active McEasy experience chip is useful, but making only one active can imply the current role is McEasy even though the date ended in May 2025.
- The contact section repeats the same CTA as the hero. That is fine, but the second instance should feel like the primary endpoint, not just a repeated control.
